Catch the flipped bit: parity, ECC and memory channels

About 10 minutes. Yesterday you learned which stick fits. Today: two things you can't see by looking at it. Error checking (non-parity, parity, ECC) and multi-channel memory (why two sticks beat one).[1] The win: read a RAM spec line and know whether it suits a server, and set up a desktop so its memory runs at full speed.

Why this matters at work

Two common hardware requests: "upgrade this PC from 8 to 16 GB" and "order RAM for the server". For the PC, two matching 8 GB sticks usually beat one 16 GB stick, because they run in dual channel. For the server, the stick must be ECC, and a regular desktop stick won't do. Both look almost identical on the order page; the spec line is the difference.

1. Bits can flip

RAM stores each bit as a tiny electrical charge. Now and then one flips from 0 to 1 (or back) on its own. On a laptop that's a rare crash. On a server running for months with lots of memory, it can silently corrupt data. Three kinds of memory handle this differently:[1]

TypeWhat it doesWhere you see it
Non-parityNo checking at all. A flipped bit goes unnoticed.Almost every desktop and laptop
ParityAdds one check bit per byte. It can detect a single-bit error but can't fix it; the system usually halts.Older systems; rare today
ECC (error-correcting code)Extra check bits that detect and correct a single-bit error on the fly, so the system keeps running. It can also detect (not fix) some multi-bit errors.Servers, workstations

How parity works: the extra bit makes the count of 1s come out even (even parity) or odd (odd parity). If one bit flips, the count is wrong, so the error shows. But it can't say which bit flipped, and two flips cancel out. ECC uses more check bits: a standard ECC module is 72 bits wide instead of 64, with 8 bits for error correction.[2]

Rule of thumb

Parity finds. ECC finds and fixes. You can't tell them apart by looking: check the spec.[1] And ECC only works if the motherboard and CPU support it; that's why it lives in servers.

Trap: every DDR5 stick has on-die ECC inside each chip. That's not the same as an ECC module: it fixes errors inside the chip only, not on the way to the CPU. A "DDR5" spec line alone does not mean "ECC memory".[3]

2. Multi-channel: more lanes to the CPU

The memory controller talks to RAM over channels, like lanes on a road. With one stick, only one channel is in use. Put matching sticks in the right slots and the controller uses two channels at once (dual channel), roughly doubling bandwidth. Some boards support triple or quad channel.[1]

  • Match the sticks: same size and speed, ideally the same model, installed as a set (pair, triple, quad).
  • Use the right slots: boards often color-code the slots that go together; the motherboard manual says which to fill first.[1]
  • Integrated graphics use system RAM, so laptops without a separate graphics card feel the single-channel penalty most.

Try it (2 minutes)

  1. In Windows PowerShell, check whether the board uses error correction:
    Get-CimInstance Win32_PhysicalMemoryArray | Select-Object MemoryErrorCorrection
    3 = none, 4 = parity, 5 = single-bit ECC, 6 = multi-bit ECC.[4][5]
  2. Check each stick's width and slot:
    Get-CimInstance Win32_PhysicalMemory | Format-Table DeviceLocator, Capacity, DataWidth, TotalWidth
    DataWidth 64 / TotalWidth 72 points to ECC; 64 / 64 is regular memory.[2] Some systems report these fields wrongly, so treat it as a hint and confirm with the spec sheet.
A desktop shows two DeviceLocator entries, both 8 GB, in slots the manual pairs together. A third command returns MemoryErrorCorrection 3. What does that tell you? (then click to check)

The pair can run in dual channel (matching sizes in paired slots), and the system uses no error correction (3 = none): ordinary non-parity desktop memory. Normal for a workstation that isn't a server.

Practice

Answer from memory before scrolling back up.

A file server must keep running even if a single memory bit flips. Which memory should you order?

ECC detects and corrects single-bit errors, so the server keeps running. Parity only detects (and usually halts the system). DDR5's on-die ECC protects only inside the chip; it doesn't make a stick an ECC module.

A system halts with a memory error message. Its RAM could detect the error but not fix it. What kind of memory is it?

Parity notices that the count of 1s is wrong but can't tell which bit flipped, so it can't fix it. ECC would have corrected a single-bit error; non-parity wouldn't have noticed at all.

A user's desktop has one 16 GB stick. They want it faster for the same capacity. What's the best change?

Two matching sticks in the paired (often color-coded) slots run in dual channel, roughly doubling memory bandwidth at the same 16 GB. A mismatched 8 GB stick may not run fully dual channel, and ECC needs board support.

Two RAM sticks look identical. How do you tell whether one is ECC?

ECC, parity and non-parity modules look very similar; you have to check the specifications.[1] Pins and the notch tell you the generation (lesson 0047), not error checking.

From memory: one line each for non-parity, parity and ECC. (then click to check)

Non-parity: no checking. Parity: detects a single-bit error, can't fix it. ECC: detects and corrects a single-bit error, keeps running; needs board support.

A cable modem's coax port uses a threaded connector; an old DSL line uses a small 4-wire plug. Name both. (lesson 0045, 3 days ago)

The coax one is an F-connector (threaded, RG-6). The DSL plug is RJ11, smaller than the 8-pin RJ45 used for Ethernet.

A monitor looks slightly blurry on an old cable with blue 15-pin plugs. Why, and what's the fix? (lesson 0041, 7 days ago)

That's VGA: analog video only, which softens at high resolutions. Move to a digital link: HDMI, DisplayPort or DVI-D.

A laptop screen is very dark, but with a flashlight you can faintly see the desktop. Which part probably failed? (lesson 0034, 14 days ago)

The backlight (or, on older LCDs, its inverter). The LCD panel still draws the picture; nothing lights it from behind.
