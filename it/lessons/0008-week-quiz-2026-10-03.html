Weekly quiz: Sep 26 – Oct 2

About 20 minutes. Fourteen questions mixing the whole first week: the four IP settings, TCP and UDP, every exam port, and Wi-Fi bands, channels and standards. The topics are shuffled on purpose, and most questions are tickets, not definitions: decide what's wrong before you decide what it's called.

How to take it

No scrolling back to the lessons until you've answered. A wrong answer now, followed by the explanation, sticks better than a right answer you looked up. Each explanation links to the lesson that taught it, so you know exactly what to reread.

A user can ping the default gateway and can ping a public server by its IP address, but Resolve-DnsName example.com times out. Which setting do you check next?

Reaching a public IP proves the IP address, mask and gateway all work: traffic gets out. Only turning names into addresses fails, which is the DNS server's job. Channel width would slow things, not break only names. See lesson 0001.

A clinic's older tablets support only 802.11a. The team is configuring new access points. Which must stay enabled so the tablets can still connect?

802.11a is a 5 GHz-only standard (54 Mbps). Backward compatibility works only within a band, so the tablets need 5 GHz. 802.11g is a 2.4 GHz standard and won't help an a-only radio. See lesson 0007.

After a firewall change, a user on a current Windows laptop can browse the web and send email, but \\fileserver\share won't open. Ping to the file server works. What's the best first test?

A \\server\share path is SMB, which modern Windows sends directly over TCP 445. Ping working means the machine is reachable, so suspect the port (lesson 0002). 389 is LDAP, 3389 is RDP and 110 is POP3. See lesson 0005.

A firewall log shows a laptop at 192.0.2.10 connecting from port 51544 to a server's port 443. Which statement is correct?

The client picks a temporary ephemeral port (51544) for each connection so the reply finds its way back. The server listens on a fixed, non-ephemeral port: 443 for HTTPS. See lesson 0002 and lesson 0003.

Users near the break room report Wi-Fi drops every time the microwave runs. Their laptops show Band : 2.4 GHz. What's the best fix?

2.4 GHz is shared with microwaves, Bluetooth and cordless gear. Moving clients to 5 GHz gets them out of that noise. Channel 12 isn't allowed in the US, and a lease renewal or DNS port wouldn't stop radio interference. See lesson 0006.

A user moves from a desktop mail app to webmail and finds years of old messages, and the folders they made in the app, missing from the server. How was the desktop app most likely set up?

POP3 downloads mail to one device and typically removes it from the server, so the messages and local folders lived only in the app. IMAP would have kept mail and folders on the server. SMTP only sends; LDAP is directory lookups. See lesson 0004.

A remote worker can SSH into a jump server and ping it, but Remote Desktop to the same server times out. What's the most likely issue?

SSH on 22 already works, so 22 isn't blocked. Remote Desktop (RDP) uses TCP 3389, the one four-digit port on the exam list. UDP 67 is DHCP and 443 is HTTPS. See lesson 0003.

After a router was replaced, every laptop that joins the guest Wi-Fi gets a 169.254.x.x address and a blank default gateway. Signal is strong. What's the most likely cause?

169.254.x.x is APIPA: Windows made up an address because no DHCP server answered its UDP 67/68 broadcast. A strong signal rules out the radio, channel 6 is a normal choice, and passwords don't change IP addresses. Check the new router's DHCP settings. See lesson 0001 and lesson 0004.

An office upgrades every access point and laptop to Wi-Fi 7, but speeds at desks barely improve. Every access point is set to 20 MHz channels on 5 GHz. What's the most likely limit?

Most of the newer standards' speed comes from wider bonded channels (plus MIMO). Locked to 20 MHz, Wi-Fi 7 can't use its headroom. Wi-Fi 7 runs on 2.4, 5 and 6 GHz, 802.11g can't use 5 GHz at all, and addresses don't have speeds. See lesson 0006 and lesson 0007.

An older internal app asks for an "LDAP server" to check sign-ins. The company uses only cloud Entra ID, with no on-premises directory. What's the core problem?

LDAP (389, or 636 for LDAPS) is how software queries a classic directory like on-premises Active Directory. Entra ID is a cloud service that apps reach over HTTPS 443, so there's no LDAP server to point the app at. See lesson 0005.

A firewall allows UDP 53 but blocks TCP 53. Most sites resolve fine, but lookups for one domain with a very large DNS record fail. Why?

DNS uses UDP 53 for small lookups because skipping TCP's handshake is faster. When an answer is too big for one UDP packet, DNS retries over TCP 53, which this firewall blocks. See lesson 0004 and lesson 0002.

netsh wlan show drivers on a laptop lists 802.11b 802.11g 802.11n 802.11a 802.11ac. The new access points run Wi-Fi 6E on 6 GHz only. What happens?

The adapter's ceiling is 802.11ac (Wi-Fi 5), which is 5 GHz only. 6 GHz needs Wi-Fi 6E or Wi-Fi 7 on both ends, so the laptop never even sees the network. A 5 GHz SSID would let it join at ac speeds. See lesson 0007 and lesson 0006.

Which of the following lists only protocols that send logins in plain text by default?

Telnet (23), FTP (20/21) and HTTP (80) are all unencrypted. Telnet and HTTP have encrypted replacements in SSH (22) and HTTPS (443). RDP (3389) is encrypted, and LDAPS (636) is LDAP wrapped in TLS. See lesson 0003 and lesson 0005.

A copier sends scan-to-email through a cloud mail provider and signs in with a username and password. Which port is it most likely configured to use?

Scan-to-email only sends, and sending is SMTP: 25 between servers, and 587 when a mail app or device submits mail with a sign-in. IMAP and POP3 fetch mail; DNS finds the server but doesn't carry the message. See lesson 0004.

Explain it in your own words

Say or write the answer before you open each one. If you can explain it to a coworker, you know it.

A user says "I can't sign in to anything" and their laptop has a 169.254.x.x address. Explain to them, without jargon, why this isn't an account problem and what you'll check. (lesson 0001, lesson 0004)

The laptop never got its network settings: it asked for them (DHCP, UDP 67/68) and nobody answered, so it made up a 169.254 address with no gateway and no DNS. It can't reach the sign-in service at all, so the password is never even checked. Check the cable or Wi-Fi connection, the switch port, and the DHCP server.

Why does a live video call use UDP while a file download uses TCP? And why can't DHCP use TCP? (lesson 0002)

TCP sets up a connection and re-sends lost data in order: right for files, where every byte matters. UDP just sends: a lost video packet is a brief glitch instead of a stall, and a late packet is useless anyway. DHCP clients have no IP address yet, so they can't set up a TCP connection; they broadcast over UDP and wait.

A manager asks why the new Wi-Fi 7 access points didn't make every laptop fast. Give two reasons. (lesson 0006, lesson 0007)

A connection runs at the best standard both ends share, so an older laptop adapter (say, Wi-Fi 5) stays at its own speed. And distance and walls matter: higher bands are faster but fade sooner, so far-away laptops get weaker signal or fall back to 2.4 GHz. (Narrow channel settings and crowded channels are good third answers.)

Walk a "the shared drive won't open" ticket from the bottom up: which checks, in which order, and which port matters at the end? (0001, 0002, 0005)

Does the PC have good IP settings (no 169.254, a gateway, a DNS server)? Does the server's name resolve? Does ping reach it? Then test the service's port: SMB on TCP 445 with Test-NetConnection. Only after a connection opens do permissions on the share come into it.
