File sharing and directory ports

About 10 minutes. The last group of exam ports: the ones that open shared drives (NetBIOS and SMB) and the ones that look up users and groups in a directory (LDAP and LDAPS). After today you have the whole Common Ports list.

Why this matters at work

"I can sign in but the shared drive won't open" and "the app can't find my account" are two different problems on two different ports. Shared drives speak SMB. Classic on-premises Active Directory answers questions over LDAP, and many companies still run it and sync it to Entra ID.[3] Entra ID itself is a cloud service that apps reach over HTTPS 443, not LDAP, which is worth knowing when an older app "needs LDAP" and there's no on-premises directory to point it at.

File sharing: old NetBIOS, modern SMB

SMB (Server Message Block) is the Windows file and printer sharing protocol: every \\server\share path and mapped drive uses it. It can travel two ways.[1]

PortProtocolTransportJob
137NetBIOS name serviceUDPFind a computer by its short NetBIOS name
138NetBIOS datagram serviceUDPSmall connectionless messages and broadcasts
139NetBIOS session serviceTCPCarry SMB the old way, over NetBIOS
445SMB (direct)TCPCarry SMB straight over TCP, no NetBIOS

The three NetBIOS ports together are called NetBIOS over TCP/IP (NetBT), from a 1987 standard.[2] Since Windows 2000, Windows can run SMB directly on TCP 445 and skip NetBIOS entirely. If both are enabled, Windows tries both at once and uses whichever answers first, so it can still talk to old systems.[4] For the exam: "NetBIOS 137–139 is the legacy path, SMB 445 is the modern one."

Security note for later (Security+ territory): SMB is for inside networks. Port 445 should never be reachable from the internet, which is why firewalls and ISPs commonly block it.

Directory: LDAP and LDAPS

PortProtocolTransportEncrypted
389LDAPTCP (UDP for some small lookups)No, by default
636LDAPS (LDAP over TLS)TCPYes, from the first byte

LDAP (Lightweight Directory Access Protocol) is how software asks a directory questions: "does this user exist?", "which groups are they in?", "what's this person's department?". Active Directory uses LDAP as its core query protocol.[3] Plain LDAP on 389 is unencrypted, so a sign-in check can cross the network readable. LDAPS wraps the same protocol in TLS on port 636: the same pattern as HTTP 80 vs HTTPS 443.[5]

Beyond the exam: LDAP on 389 can also upgrade itself to TLS mid-connection (called StartTLS), so "port 389" doesn't always mean "unencrypted". For the exam, keep it simple: 389 LDAP, 636 LDAPS.

Memory hooks

137, 138, 139: NetBIOS counts up: name, datagram, session. 445: SMB, "four-four-five, shares stay alive". 389 → 636: LDAP, then LDAPS with the S for secure, just like 80 → 443.

Try it (2 minutes)

On a work or home Windows PC, see which ports your shares and name lookups use.[6]

  1. Run net use to list mapped drives. Each one is an SMB connection.
  2. In PowerShell, test the SMB port on a file server you can already reach: Test-NetConnection followed by the server's name and -Port 445. TcpTestSucceeded : True means SMB can connect.
  3. Run nbtstat -n to see your PC's own NetBIOS names. If it lists names, NetBIOS over TCP/IP is still enabled on that adapter.
ComputerName     : fileserver.example.net
RemoteAddress    : 192.0.2.20
RemotePort       : 445
TcpTestSucceeded : True

Your output will differ. No file server handy? Try it at home against a NAS or another PC with a shared folder, or just read the steps: the command is the same one from lesson 0003 with a different port.

Practice

Answer from memory before scrolling back up.

A user on a current Windows laptop can browse the web but gets an error opening a mapped drive after a firewall change. Which port is the likely suspect?

Mapped drives are SMB, and modern Windows sends SMB directly over TCP 445. LDAP is for directory lookups, RDP for remote desktops, and a DNS failure would break web browsing too.

A team wants file servers to use only modern direct-hosted SMB and turn off the legacy path. Which ports stop being needed?

137–139 are NetBIOS over TCP/IP, the legacy way to carry SMB. Direct-hosted SMB uses TCP 445, which must stay open. 636 is LDAPS and 3389 is RDP, unrelated to file sharing.

An internal app checks users' passwords against an on-premises directory on port 389. A review flags that the check crosses the network unencrypted. What's the standard fix?

LDAPS is the same directory protocol wrapped in TLS, on TCP 636. SMB and NetBIOS carry files, not directory queries, and DNS only turns names into addresses.

A help-desk tool shows a user's department and group memberships, read live from Active Directory. Which protocol is it using?

Looking up users, groups and attributes in a directory is LDAP's whole job (TCP 389, or 636 for LDAPS). SMB shares files, SMTP sends mail and DHCP hands out IP settings.

From memory: give the ports for NetBIOS, SMB, LDAP and LDAPS, and say which is the legacy file-sharing path. (then click to check)

NetBIOS 137–139 (137, 138 UDP; 139 TCP) is the legacy path. SMB direct 445 TCP. LDAP 389, LDAPS 636.

Review: earlier lessons

Spaced retrieval: pull these from memory first, then check.

A user's email read on the laptop never shows as read on the phone. Which fetch protocol is the laptop using, and which one should it use? (lesson 0004, yesterday)

POP3 (110), which downloads mail to one device. Switch to IMAP (143, or 993 over TLS), which keeps mail on the server and syncs every device.

Ping to a server works but the app on it doesn't respond. What does that tell you, and what's the next suspect? (lesson 0002, 3 days ago)

The network path and IP settings are fine. Suspect the port: the service isn't listening, or a firewall blocks that port. Test-NetConnection with -Port checks it directly.

What's the encrypted replacement for Telnet, and on which port? (lesson 0003, 2 days ago)

SSH on TCP 22. Telnet (23) sends everything, passwords included, in plain text.
