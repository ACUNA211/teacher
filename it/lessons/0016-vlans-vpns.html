VLANs and VPNs: splitting one network, joining distant ones

About 10 minutes. Two ideas that sound alike but do opposite jobs. A VLAN takes one physical switch and splits it into several separate networks. A VPN takes devices that are far apart and makes them act as if they were on the same network, through an encrypted tunnel.[1]

Why this matters at work

"I can open the file share in the office but not from home" is usually a VPN question, not a password question. And on managed laptops, the VPN profile is often pushed by Intune rather than set up by hand, so a missing or broken profile is a device-configuration problem you can check in the admin center.[4]

VLANs: one switch, several networks

A plain switch is one broadcast domain: a broadcast (like the DHCP Discover from lesson 0014) reaches every device plugged into it. The old way to separate, say, staff from guests was to buy a second switch. A VLAN (virtual LAN) does the same in software: you assign switch ports to VLANs, and each VLAN is its own broadcast domain, as if it were a separate switch.[1]

  • Each VLAN is its own subnet, so it usually gets its own DHCP scope (one scope per subnet, lesson 0014).
  • VLANs can't talk to each other directly. Traffic between them has to go through a router (or a layer 3 switch), which is where you can filter it.[2]
  • A link that carries several VLANs between switches is a trunk. Each frame gets a small tag saying which VLAN it belongs to; the standard is 802.1Q. A normal port for one device, in one VLAN, is an access port.[2]

Typical split in a small office: staff, guest Wi-Fi, VoIP phones, printers, and the IoT and cameras from lesson 0011, each in its own VLAN. A guest can't even see the file server's broadcasts.

VPNs: an encrypted tunnel across the internet

A VPN (virtual private network) encrypts traffic and sends it through the public internet to a device that decrypts it on the other side. That device is a VPN concentrator: often a feature of the firewall, sometimes a dedicated box or a cloud service.[1]

TypeWho's at each endExample
Client-to-site (remote access)One device running VPN client software ↔ the office's concentratorA laptop at home reaching the file share
Site-to-siteFirewall at one office ↔ firewall at another. Always on; users run nothing.A branch office reaching headquarters' servers

Two more words you'll see on a client-to-site VPN profile:

  • Full tunnel: all traffic goes through the VPN, even web browsing. Split tunnel: only traffic for company networks goes through it; the rest goes straight to the internet.[3]
  • Always On: the VPN connects by itself (for example at sign-in), so the user never has to click Connect. Intune can set this in a Windows VPN profile.[3]
Memory hooks

VLAN = divide (one switch, many networks). VPN = connect (far away, feels local). Client-to-site = one person, site-to-site = whole office.

Try it (2 minutes)

On a Windows PC, open PowerShell and list the VPN profiles in your user's phone book:[5]

Get-VpnConnection | Format-List Name, ServerAddress, TunnelType, SplitTunneling, ConnectionStatus

Example output (yours will differ, and a home PC may show nothing at all):

Name             : Office VPN
ServerAddress    : vpn.example.com
TunnelType       : Ikev2
SplitTunneling   : True
ConnectionStatus : Disconnected

SplitTunneling : True means only company traffic uses the tunnel. Add -AllUserConnection to see device-wide profiles. Many company VPNs use a vendor's own app instead of the built-in Windows client; those may not appear here, but they do add an extra adapter in ipconfig /all while connected.

Practice

Answer from memory before scrolling back up.

An office wants guest Wi-Fi users kept completely apart from staff PCs, but there's only one switch and no budget for another. What should they set up?

A VLAN splits one physical switch into separate broadcast domains, exactly as a second switch would. Guests and staff end up on different subnets, and traffic between them must go through a router where it can be blocked. A VPN connects distant places; it doesn't divide a local network.

A company opens a branch office. Everyone there needs the headquarters file server all day, and nobody should have to start any software. Which option fits?

Site-to-site joins two whole networks: the firewalls (or concentrators) at each office hold the tunnel up, so users do nothing. Client-to-site is for one device at a time, with client software on it. A trunk carries VLANs between switches in the same building, not across the internet.

A remote worker on VPN reports that video calls and web browsing are very slow, but only while connected. The profile sends every packet to the office. Which setting is most likely involved?

With a full tunnel, even internet traffic travels to the office first and back out, so the office's connection becomes the bottleneck. A split tunnel sends only company traffic through the VPN. Full tunnel is sometimes chosen on purpose, for inspection; the trade-off is speed.

A printer was moved to a new "Printers" VLAN. Staff PCs, on the staff VLAN, can no longer print to it, though the printer works from its own VLAN. What's missing?

VLANs are separate networks, so traffic between them must pass through a router or layer 3 switch, and the rules there must allow it (here: staff → printer on its print ports). Without that, the VLAN is doing exactly its job: keeping things apart.

From memory: explain the difference between a VLAN and a VPN in one sentence each, and name the two kinds of VPN. (then click to check)

VLAN: splits one physical switch into several separate broadcast domains (networks). VPN: an encrypted tunnel over the internet that makes distant devices act as if they're on the company network. Kinds: client-to-site (one device with client software) and site-to-site (whole office to whole office, between firewalls or concentrators).

Review: earlier lessons

Spaced retrieval: pull these from memory first, then check.

A DHCP Discover is a broadcast, which stops at the router. How can one DHCP server still hand out addresses to several subnets (or several VLANs)? (lesson 0014, 2 days ago)

The router forwards the request as a DHCP relay (Cisco: "IP helper"). The server sees which subnet it came from and answers from that subnet's scope. One scope per subnet.

Which wireless technology works at about 4 cm and is used for tap-to-pay and some security keys, and which uses tags that may have no battery at all? (lesson 0009, 7 days ago)

NFC (13.56 MHz, a few centimeters): tap-to-pay, FIDO2 keys. RFID: passive tags have no battery and are powered by the reader's signal.

What's an ephemeral port, and which side of a connection picks it? (lesson 0002, 14 days ago)

A temporary, high-numbered port the client picks for its end of a connection, so replies from the server's well-known port (like 443) find their way back to the right app.
