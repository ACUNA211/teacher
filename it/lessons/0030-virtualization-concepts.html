A computer inside a computer: why we run virtual machines

About 10 minutes. New domain: Virtualization & cloud (11% of Core 1). A virtual machine (VM) is a whole computer made of software: its own operating system, with CPU time, memory, disk and network handed to it by the real machine underneath.[1] The win today: for any "can we safely try this?" problem, name which of the four uses of a VM fits.

Why this matters at work

Rolling a change out to every laptop at once is how one bad setting becomes a hundred tickets. A test VM lets you try a new app, an update or a device policy on a machine nobody depends on, and throw it away afterwards. Windows VMs can be enrolled as test devices too, so a policy can reach a pilot VM before it reaches real users.

Three words first

  • Host: the physical computer, and the operating system running on it.
  • Guest: an operating system running inside a VM. One host can run several guests at once, each separated from the others.
  • Hypervisor (virtual machine manager): the software that creates the VMs, shares out CPU, memory and networking, and keeps the guests apart.[2] Its two types are the next lesson.

Four reasons to run a VM

UseThe problem it solvesExample
SandboxingTry something without risk to the host or the production network. The sandbox is isolated, and when it's thrown away its data goes with it.[1]Open an unknown installer, test a risky setting
Developing and testing softwareDevelopers need clean, repeatable machines to build and test on, without breaking their own computer.[1]Test an app update on a fresh Windows build
Legacy softwareAn application only runs on an older operating system. Build a VM with that old OS and keep the modern desktop for everything else.[2]An old line-of-business app that needs an old Windows version
Cross-platformRun a different operating system than the host: Linux on a Windows PC, Windows on a Mac, several OS versions side by side.[1]Check that a web app works on another OS and browser

Snapshots: the undo button

Most hypervisors can save a VM's exact state as a snapshot (Hyper-V calls it a checkpoint). Break something, revert, and you're back to the moment before the test. That's what makes a VM such a good sandbox: the same clean starting point, every time.

Watch out: legacy VMs

A VM keeps old software running, but it doesn't make an unsupported OS safe. It still gets no security updates, so give a legacy VM only the network access it truly needs.

Memory hook

Host = the real machine. Guest = the OS inside the VM. Hypervisor = the referee between them. The four uses: sandbox, develop, legacy, cross-platform.

Try it (3 minutes)

Windows has a disposable VM built in: Windows Sandbox. Everything you do inside it is discarded when you close it.[3]

  1. Is virtualization on? Task Manager → Performance → CPU. Look for Virtualization: Enabled. If it says Disabled, it's switched off in the UEFI/BIOS settings.
  2. Or run systeminfo and read the last lines. Either you'll see Hyper-V Requirements (each should say Yes), or "A hypervisor has been detected", which means one is already running.[4]
  3. On Pro, Enterprise or Education (not Home): search for Turn Windows features on or off, tick Windows Sandbox, restart. Or, in an admin PowerShell: 
    Enable-WindowsOptionalFeature -Online -FeatureName Containers-DisposableClientVM
  4. Open Windows Sandbox, create a file on its desktop, close it, open it again. The file is gone: a sandbox in one click.

Needs at least 4 GB of RAM (8 GB recommended) and two CPU cores.[3] On a work laptop, check with whoever manages it before turning on Windows features.

Practice

Answer from memory before scrolling back up.

A department still relies on an old accounting app that won't install on current Windows. Staff have modern laptops. What's the cleanest fix?

That's the legacy software use: a VM runs the older OS the app needs, and the laptop keeps its supported, patched OS for everything else. Downgrading or stopping updates makes every laptop less secure. Keep the legacy VM's network access to the minimum, since its OS gets no updates.

You want to test a new device setting on a Windows machine, break it on purpose, and get back to the exact starting point several times. What makes that fastest?

A snapshot (a checkpoint, in Hyper-V) saves the VM's exact state; reverting returns to it in seconds. Reinstalling or using a second laptop works but is slow, and a file checker only repairs system files, not your settings.

A web developer on a Windows PC must check that their site works on a Linux desktop browser, without buying another computer. Which use of virtualization is this?

Cross-platform: a guest OS different from the host (Linux on Windows here). Legacy is about an older OS an app needs; sandboxing is about isolating risk; virtual desktop infrastructure (desktops served from a data center) comes in the next lesson.

A user turns on Windows Sandbox, tests an installer inside it, closes it, and reopens it the next day. The installed program is gone. Why?

Windows Sandbox is disposable by design: nothing persists after it closes, and the next launch starts clean. That's exactly what a sandbox is for. To keep a test machine between sessions, use a full VM (Hyper-V, for example) with snapshots instead.

From memory: host, guest, hypervisor, and the four uses of a VM. (then click to check)

Host: the physical machine and its OS. Guest: the OS inside a VM. Hypervisor: creates the VMs, shares out the hardware and keeps them apart. Uses: sandboxing (isolated, throwaway), developing/testing software, legacy software (old OS in a VM), cross-platform (a different OS than the host).

Review: earlier lessons

Spaced retrieval: pull these from memory first, then check.

What does a phone need to work out its own position by GPS, and what does it lean on indoors? (lesson 0027, 3 days ago)

Signals from at least four satellites (three for position, one more to correct the clock). Indoors it falls back on nearby Wi-Fi and cell towers to estimate location, which is why it gets less precise inside buildings.

A technician is about to replace a laptop's drive. What should they do first if the drive is BitLocker-encrypted, and what are the two ways to move to the new SSD? (lesson 0023, 7 days ago)

Make sure the recovery key is available (and suspend BitLocker for planned hardware work, so the change doesn't trigger recovery). Then either clone the old drive (keeps Windows, apps and files) or do a fresh install and restore files from backup.

A remote user's VPN is set to full tunnel. Their video calls are slow. What does full tunnel do, and what would split tunnel change? (lesson 0016, 14 days ago)

Full tunnel sends all traffic through the VPN to the company network first. Split tunnel sends only company traffic through the VPN, so internet and cloud traffic (like video calls) goes straight out, faster.
