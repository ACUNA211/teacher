DNS records: what a name can answer

About 10 minutes. You know DNS turns names into IP addresses (lesson 0001) over UDP 53 (lesson 0004). But a DNS server holds more than addresses: it stores records of different types, and each type answers a different question.[1] Today: the five you'll read most. Tomorrow: the three email-security records built on top of TXT (SPF, DKIM, DMARC).

Why this matters at work

When an organization adds its own domain to Microsoft 365, the admin center asks for exactly these records: a TXT record (MS=ms…) to prove you own the domain, an MX record so mail goes to Exchange Online, and a CNAME called autodiscover so Outlook can find its settings.[2] "Outlook can't find my mailbox" or "the domain won't verify" usually means one of those records is missing or wrong.

The five record types

Each row is one question you can ask DNS about a name. Examples use example.com and documentation addresses (never real ones).

TypeQuestion it answersExample answer
AWhat's the IPv4 address of this name?www.example.com → 192.0.2.10
AAAAWhat's the IPv6 address of this name?www.example.com → 2001:db8::10
CNAMEIs this name an alias? What's the real (canonical) name?autodiscover.example.com → autodiscover.outlook.com
MXWhich server receives email for this domain?example.com → 10 mail.example.com
TXTIs there any text attached to this name?example.com → "MS=ms12345678"

Details that show up on the exam (and at work)

  • AAAA is "quad A": four A's because an IPv6 address (128 bits) is four times as long as IPv4 (32 bits). A name can have both an A and an AAAA record.
  • CNAME points at a name, never at an address. The client then looks up that name's A or AAAA record. Move a service, update one record, and every alias follows. A name that has a CNAME can't have any other records,[3] which is why the bare domain (example.com, which needs MX and TXT) usually can't be a CNAME.
  • MX has a priority number: lower wins. A sending server tries the lowest number first and moves to the next only if that one doesn't answer.[4] MX records also point at a name, which then needs its own A/AAAA record.
  • TXT is free text that other services read: proof of domain ownership (like Microsoft's MS= value) and the email rules you'll meet tomorrow.[1]
  • Every record has a TTL (time to live, in seconds): how long clients and other DNS servers may cache the answer. A change can take up to the old TTL to be seen everywhere; Microsoft tells admins to allow time for DNS changes before retrying verification.[2]
Memory hooks

A = Address (v4). AAAA = four times bigger (v6). CNAME = Common NAME, an alias. MX = Mail eXchanger, lowest number first. TXT = notes for other services.

Try it (2 minutes)

Ask DNS for each type yourself. In PowerShell:[5]

Resolve-DnsName microsoft.com -Type A
Resolve-DnsName microsoft.com -Type AAAA
Resolve-DnsName microsoft.com -Type MX
Resolve-DnsName microsoft.com -Type TXT

Look at the columns: Type, TTL, and for MX the NameExchange (mail server) and Preference (priority). The TXT answer will be long: count how many lines start with v=spf1 or a …-verification= value. That's tomorrow's lesson showing up early.

On any PC, the older tool works too: nslookup -type=mx microsoft.com. Try your own organization's domain as well, but keep the results off any public page.

Practice

Answer from memory before scrolling back up.

A new web server only has an IPv6 address. Users on IPv6 can't reach shop.example.com by name. Which record is most likely missing?

AAAA maps a name to an IPv6 address. An A record holds only IPv4; MX is for mail and TXT holds text, neither gives a web address.

A domain has two MX records: 10 mx1.example.com and 20 mx2.example.com. Both servers are online. Where does incoming mail go first?

MX priority: the lowest number is preferred. mx2 (20) only gets mail when mx1 (10) doesn't answer. Equal numbers would share the load.

An admin adds a domain to a cloud service, which asks them to prove they own it without changing where mail or the website goes. Which record do they add?

A TXT record holds a value the service gave you; it checks DNS for it, and nothing else about the domain changes. Changing MX or A would move mail or the website, and the bare domain can't be a CNAME because it already has other records.

Outlook on new laptops can't set itself up for a user's mailbox, but mail and web browsing work. Which record should you check first?

For Microsoft 365, Outlook finds its settings through autodiscover.<domain>, a CNAME pointing at autodiscover.outlook.com. Mail arriving fine means MX is OK; web browsing working means the A record is OK.

From memory: name the five record types and the question each one answers. (then click to check)

A: IPv4 address. AAAA: IPv6 address. CNAME: the real name behind an alias. MX: which server receives mail (lowest number first). TXT: text for other services, such as ownership proof.

Review: earlier lessons

Spaced retrieval: pull these from memory first, then check.

A website runs on four servers but customers use one address, and a crashed server goes unnoticed. Which appliance does that, and how is it different from a proxy? (lesson 0011, 1 day ago)

A load balancer: it faces inward and spreads requests across your servers. A proxy faces outward and makes requests on behalf of your users.

Which wireless technology works at about 4 cm, at 13.56 MHz, and is used for tap-to-pay and some security keys? (lesson 0009, 3 days ago)

NFC (near-field communication). It's built on RFID, but designed for very short, two-way exchanges.

Which port does SMB use for file sharing today, and which port does LDAPS use? (lesson 0005, 7 days ago)

SMB: TCP 445 (direct-hosted, no NetBIOS needed). LDAPS: TCP 636 (plain LDAP is 389).
