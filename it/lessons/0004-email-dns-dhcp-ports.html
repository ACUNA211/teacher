Email, DNS and DHCP ports

About 10 minutes. By the end you know the ports that send and fetch email, the port that turns names into addresses, and the two ports a device uses to get its IP settings in the first place.

Why this matters at work

Two of the four settings from lesson 0001 come from these protocols: DHCP hands out the address, DNS finds everything by name. And a classic helpdesk ticket, "my scanner (or an old app) can't send email any more", is almost always about SMTP: which port it uses and whether it still signs in the old way. Microsoft 365 turned off basic (password-only) sign-in for POP and IMAP in 2022 and is doing the same by default for SMTP sign-in at the end of 2026.[3]

Email: one port to send, two ways to fetch

Email uses separate protocols for sending and reading. All three run over TCP.[1]

PortProtocolJob
25SMTPSend mail, and pass it between mail servers
110POP3Fetch mail: download it to one device
143IMAPFetch mail: keep it on the server, synced to every device

POP3 vs IMAP is a favourite exam question. POP3 is "post office": you collect the mail and take it home, typically removing it from the server. IMAP leaves the mail and its folders on the server, so phone, laptop and web see the same inbox.[4] Anyone with more than one device wants IMAP.

Beyond the exam list: those three are the plain versions. In real setups you'll see the encrypted ones: 587 for a mail app submitting mail with a sign-in,[5] 993 for IMAP over TLS and 995 for POP3 over TLS.[4] Same idea as HTTP 80 vs HTTPS 443 from lesson 0003.

DNS and DHCP: the two that use UDP

PortProtocolTransportJob
53DNSUDP (TCP for big answers)Turn a name into an IP address
67, 68DHCPUDPHand a device its IP settings automatically

DNS lookups are tiny, one question and one answer, so UDP's no-handshake speed wins. When an answer is too big for one UDP packet, or when DNS servers copy whole zones to each other, DNS switches to TCP 53.[2] For the exam: "DNS, 53, mostly UDP".

DHCP has two ports: the server listens on 67 and the client listens on 68.[6] It has to be UDP: a device asking for an address doesn't have an address yet, so it can't set up a TCP connection. It just broadcasts "is there a DHCP server out there?" and waits.

Memory hooks

25: SMTP sends. 110 < 143: the older POP3 has the smaller number, the newer IMAP the bigger one. 53: DNS. 67/68: DHCP, server first, then client.

Try it (2 minutes)

See DNS and DHCP at work on your own PC.[7]

  1. Run ipconfig /all and find your adapter. The DHCP Server line is the machine that answered your port-67 broadcast; DNS Servers is where your port-53 questions go.
  2. In PowerShell, ask DNS for a website's address: Resolve-DnsName example.com. That was one small UDP 53 exchange.
  3. Now ask where a domain's email goes: Resolve-DnsName -Type MX followed by a domain you use for email. The NameExchange column is the mail server other servers deliver to over SMTP 25.
Name             Type  NameExchange                   Preference
----             ----  ------------                   ----------
example.net      MX    mail.example.net               10

Your output will differ. If ipconfig shows no DHCP server and a 169.254.x.x address, you already know the story from lesson 0001: the port-67 broadcast got no answer.

Practice

Answer from memory before scrolling back up.

A user reads email on a laptop and a phone. Messages read on the laptop never show up on the phone. Which fetch protocol is the laptop probably using?

POP3 downloads mail to one device and usually removes it from the server, so the phone never sees it. IMAP keeps mail on the server and syncs every device. SMTP only sends, and DNS isn't email at all.

A multifunction printer's scan-to-email feature stopped working. Receiving mail isn't involved. Which protocol should you check first?

Scan-to-email only sends, and sending is SMTP (port 25, or 587 with a sign-in). IMAP and POP3 are for fetching mail. DHCP matters only if the printer has no IP address at all.

A firewall rule allows only TCP traffic. New laptops on that network end up with 169.254.x.x addresses. Why?

DHCP runs over UDP 67 (server) and 68 (client). Block UDP and the laptops never get a lease, so they fall back to an APIPA 169.254 address. 110 is POP3, 143 is IMAP, and SMTP uses TCP.

Why does DNS normally use UDP port 53 rather than TCP?

A lookup is one small question and one small answer, so TCP's setup would cost more than the data. UDP adds no encryption, and DNS does use TCP 53 for large answers and zone transfers.

From memory: give the ports for SMTP, POP3, IMAP, DNS and DHCP, and say which use UDP. (then click to check)

SMTP 25, POP3 110, IMAP 143 (all TCP). DNS 53 (mostly UDP) and DHCP 67/68 (UDP).

Review: earlier lessons

Spaced retrieval: pull these from memory first, then check.

Which two console protocols do the same job, which one should you use, and on what ports? (lesson 0003, yesterday)

Telnet (23) and SSH (22). Use SSH: it encrypts the whole session, while Telnet sends everything, passwords included, in plain text.

A user can browse the web but Remote Desktop to their office PC times out. Which port do you suspect? (lesson 0003, yesterday)

TCP 3389, RDP. Browsing works, so 443 is fine.

A PC can reach a server by IP address but not by name. Which of the four settings is the suspect? (lesson 0001, 3 days ago)

The DNS server. Addresses work, names don't, so the name-to-address step is failing. Today you learned that step travels on port 53.
