Middleboxes and things you can't patch

About 10 minutes. Yesterday was servers that hand things out. Today finishes objective 2.3 with two more groups:[1] internet appliances, boxes that sit in the path of traffic and act on it, and legacy, embedded, SCADA and IoT devices, which do one job and can't be managed like a normal PC.

Why this matters at work

A sign-in or device-enrollment problem that only happens on the office network (and works fine on a phone hotspot) often points at a box in the path: a proxy or security appliance that inspects encrypted traffic. Microsoft recommends letting trusted Microsoft 365 traffic bypass that kind of inspection,[3] and lists Intune service addresses that shouldn't be inspected either.[4] "Works at home, fails at the office" → think middlebox.

Part 1: Internet appliances (in the path)

All four sit between users and somewhere else, and every packet that passes can be checked, changed, or sent elsewhere.

ApplianceSits betweenDoes
Spam gatewayThe internet and the mail serverFilters unwanted and malicious email before it reaches inboxes. Often a cloud service.
All-in-one security appliance (UTM)The internal network and the internetOne box for many jobs: firewall, URL filtering, malware and spam scanning, IDS/IPS, VPN endpoint, bandwidth control.[1]
Load balancerUsers and a group of serversSpreads requests across several servers behind one address; if one server fails, it stops sending traffic there.
Proxy serverUsers and the internetMakes requests on behalf of users: can cache pages, filter URLs, scan content and log access.

The pair the exam likes to mix up:

  • Load balancer faces inward: it protects and scales your servers. Users outside see one website; behind it, many servers share the work.[1]
  • Proxy faces outward: it stands in for your users. The website sees the proxy's request, not the user's PC.

UTM stands for unified threat management: the "all-in-one" name and the acronym mean the same thing. The trade-off: simple to run, but one box is now a single point of failure for everything.

Part 2: Devices you can't manage like a PC

TypeWhat it isExample
Legacy systemOld hardware or software, often no longer supported by its vendor, still running something importantAn old server that runs one business app nobody can migrate
Embedded systemA computer built into a device for one job; you usually can't reach its operating systemDoor badge reader, alarm panel, time clock
SCADA / ICSSupervisory control and data acquisition: industrial control systems that run physical processes, often spread over large areas[2]Power grid, water treatment, pipelines, factory lines
IoTInternet of things: everyday devices with a network connection, usually over Wi-FiSmart thermostat, lights, video doorbell, smart speaker

What they share: you often can't install patches or security software on them yourself, and some can't be patched at all. So the standard protection is segmentation: put them on their own separate network so a compromised device can't reach everything else.[1] SCADA networks are usually kept fully apart from the office network and the internet.[2] At home, the guest Wi-Fi is the simplest IoT segment.[5]

Memory hooks

Load balancer guards the servers; proxy speaks for the users. UTM = all-in-one = one box, many jobs. Can't patch it? Wall it off (segment it).

Try it (2 minutes)

Does your Windows PC send traffic through a proxy? Open Command Prompt or PowerShell and run:

netsh winhttp show proxy

On a PC with no system proxy you'll see:

Current WinHTTP proxy settings:

    Direct access (no proxy server).

This shows the WinHTTP proxy, the one Windows services and many background apps use.[6] Browsers usually follow a separate setting: Settings → Network & internet → Proxy. If either one names a proxy server, every web request from that app goes through it first. A wrong or unreachable proxy looks like "the internet is down" for some apps while others work fine.

Practice

Answer from memory before scrolling back up.

The company website runs on four web servers, but customers only ever use one address. When one server crashes, customers don't notice. Which device makes that possible?

A load balancer sits in front of a group of servers behind one address, shares requests between them, and stops sending traffic to a server that fails. A proxy acts for users going out, not for your servers.

A small office wants one device that handles its firewall, VPN, URL filtering and malware scanning. What is that device called?

UTM (unified threat management), also called an all-in-one security appliance, combines many security jobs in one box. SCADA controls industrial processes; print and syslog servers are server roles from lesson 0010.

A building's badge readers run firmware you can't update yourself, and the vendor no longer releases patches. What's the best way to reduce the risk?

Embedded and legacy devices often can't be patched or run security software, so you isolate them: segmentation keeps a compromised reader from reaching the rest of the network. A public address would expose them more, not less.

Users at the office can browse most sites, but the web filter logs show every request coming from one internal address instead of from each PC. Why?

A proxy server makes requests on behalf of users, so the outside site (and anything logging after the proxy) sees the proxy's address. DHCP gives each PC its own address; a spam gateway handles email, not web traffic.

From memory: name the four internet appliances and say, for each, what it sits between. (then click to check)

Spam gateway: internet ↔ mail server. All-in-one / UTM: internal network ↔ internet. Load balancer: users ↔ a group of servers. Proxy: users ↔ the internet, making requests for them.

Spaced retrieval: pull these from memory first, then check.

A user signs in fine, but is refused access to an app their team isn't assigned. Which of the three A's blocked them, and which A would you read to see the attempt? (lesson 0010, 1 day ago)

Authorization blocked them (they proved who they are, but aren't allowed). Accounting recorded the attempt: in Entra ID, that's the sign-in logs.

Which port and transport does DNS use for a normal name lookup, and which ports does DHCP use? (lesson 0004, 7 days ago)

DNS: UDP 53 for normal lookups (TCP 53 for large answers and zone transfers). DHCP: UDP 67 (server) and UDP 68 (client).

Name the four IP settings every device needs to reach the internet. (lesson 0001, 10 days ago)

IP address, subnet mask, default gateway and DNS server.
