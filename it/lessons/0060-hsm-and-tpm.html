One device or many: TPM and HSM

About 10 minutes. In lesson 0054 you found the TPM header and checked Get-Tpm. Today: what a TPM actually does, and its big sibling in the data center, the HSM.[1] The win: given a scenario, say whether it's a TPM job or an HSM job, and explain why a BitLocker-encrypted drive can't just be moved to another PC.

Why this matters at work

Three things you deal with lean on the TPM: BitLocker keeps its key sealed in it, Windows Hello keys can be bound to it so they can't be copied off the device, and Intune compliance policies can require a TPM.[2][4] When a user hits a BitLocker recovery screen after a firmware change, the TPM is why.

1. Two kinds of hardware for keys

Both are dedicated cryptographic hardware: they create keys, keep them, and use them, so the secret key doesn't have to sit in ordinary memory or on disk. The difference is scope.[1][3]

TPM (Trusted Platform Module)HSM (Hardware Security Module)
WhereInside one computer: on the motherboard, a plug-in module, or firmware in the CPU (Intel PTT, AMD fTPM)A separate device in a data center: a hardened server or a plug-in card
ServesOne system: protects data on that deviceMany systems: central, large-scale key management
DoesRandom numbers, key generation, keys burned in at manufacture, sealing keys to a known-good bootStores keys for many servers, often with redundancy across devices; can offload encryption from busy servers
ExampleBitLocker on a laptop; Windows 11 needs TPM 2.0A web farm's TLS keys; a certificate authority's signing key

2. How the TPM guards BitLocker

During startup, each piece of boot code is measured (hashed) and recorded in the TPM. BitLocker's key is sealed to those measurements: the TPM releases it only if the boot looks the same as when it was sealed.[2] That gives you two everyday effects:

  • Drive moved to another PC: a different TPM, so no key. The data stays unreadable without the recovery key.
  • Firmware or boot changes (a BIOS update, Secure Boot toggled, a boot-order change): the measurements differ, so BitLocker asks for the recovery key. That's why you suspend BitLocker before planned firmware work (lesson 0023).

The TPM also has anti-hammering: after too many wrong guesses at a TPM PIN it locks out for a while, so the key can't be brute-forced.[2]

Rule of thumb

TPM = one device's vault. HSM = the data center's vault. Laptop, BitLocker, Windows 11, Windows Hello → TPM. Many servers, a certificate authority, offloading TLS → HSM.

Try it (2 minutes)

See the TPM doing its job for BitLocker. Open Command Prompt or PowerShell as administrator and run:[5]

manage-bde -protectors -get C:

On a BitLocker-protected PC you'll usually see two key protectors: TPM (unlocks automatically at a normal boot) and Numerical Password (the 48-digit recovery key, with its ID). If the drive isn't encrypted, it says no key protectors were found.

Before checking: why does a normal boot never ask the user for anything, yet the drive is still safe if the laptop is stolen? (then click to check)

The TPM protector releases the key automatically, but only on this PC with an unchanged boot. A thief who pulls the drive gets nothing; booting something else changes the measurements. (A TPM + PIN protector adds a typed PIN for extra protection.)

Practice

Answer from memory before scrolling back up.

A company runs dozens of web servers and wants their TLS private keys kept in one hardened place, with the encryption work taken off the servers' CPUs. What fits?

An HSM is centralized key management for many systems and can offload cryptography in hardware.[1] A TPM protects only the one machine it's in.

A laptop's SSD is removed and put into an identical laptop. Windows won't start and BitLocker asks for a recovery key. Why?

BitLocker's key is sealed in the original laptop's TPM. The second laptop's TPM doesn't have it, so only the recovery key unlocks the drive.[2] Identical models still have different TPMs.

After a BIOS update, a user's laptop shows the BitLocker recovery screen at startup. Nothing else changed. What's the best explanation?

New firmware means different measurements in the TPM, so it won't release the sealed key; BitLocker falls back to the recovery key.[2] Prevent it next time by suspending BitLocker before the update.

Which of these is a job for a TPM rather than an HSM?

A TPM secures data on its own device, like a laptop's BitLocker key.[1] The other three are many-system, centralized jobs: HSM territory.

From memory: one sentence each on what a TPM is and what an HSM is, and the one word that separates them. (then click to check)

TPM: crypto hardware inside one computer that generates and protects that device's keys. HSM: a dedicated, centralized device that stores and uses keys for many systems. The word: scope (one device vs. many).

Which firmware password lets anyone power on a PC but stops them changing the boot order? (lesson 0059, 1 day ago)

The supervisor/admin password. A user/system password would stop the PC from starting at all.

A customer wants the smallest standard board for a tiny kiosk PC with one expansion card. Which form factor, and roughly how big? (lesson 0053, 7 days ago)

Mini-ITX: about 17 × 17 cm, one expansion slot, and it uses a subset of ATX mounting holes, so it fits many ATX cases.

Windows Sandbox: what happens to files inside it when you close it, and which firmware setting must be on for it to run? (lesson 0030, 30 days ago)

Everything is discarded: nothing persists. It needs virtualization (Intel VT-x / AMD-V) enabled in the BIOS/UEFI, plus a Pro, Enterprise or Education edition.
