Whose cloud, and how much of it: deployment and service models

About 10 minutes. Yesterday ended with VMs running in someone else's data center. That's the cloud. A+ asks two questions about any cloud service: who owns and shares it (public, private, hybrid, community) and how much of the stack you rent (IaaS, PaaS, SaaS).[1] The win: read a scenario and name both.

Why this matters at work

Microsoft 365 is SaaS: Microsoft runs the servers, the OS and the app. But in every model the customer still owns its data, accounts, access and devices.[3] So a phished account or an over-shared file is your job, not the provider's. And a company that syncs its on-premises Active Directory accounts into Entra ID is running a hybrid setup; Microsoft literally calls it hybrid identity.[4]

Deployment models: who owns and shares it

ModelWhat it isTrade-off
PublicA provider's cloud, open to anyone who pays; many customers share huge pools of hardware[1]No hardware to buy, scales fast; less control
PrivateOne organization's own cloud, usually in its own data center[1]Full control of the data; you buy and run everything
HybridA mix: some parts private, some in a public cloud, working together[1]Keep sensitive pieces in-house, burst the rest; more to connect and secure
CommunitySeveral organizations with the same needs (say, the same regulations) chip in for shared cloud equipment[1]Private-cloud benefits at a shared cost

Service models: how much you rent

Picture the stack from the bottom: building, hardware, network → virtualization → OS → runtime → app → data. Each model moves the line where the provider stops and you start.[2]

ModelProvider runsYou runExamples
IaaS (infrastructure)Hardware, storage, network, hypervisorThe OS, its patches, the apps, the dataCloud VMs (Azure Virtual Machines, Amazon EC2)
PaaS (platform)All of the above plus the OS and runtimeYour code and its dataApp hosting (Azure App Service, Google App Engine)
SaaS (software)Everything up to the finished app[1]Your data, users and settingsMicrosoft 365, Gmail, Salesforce

Responsibility shrinks as you go up: IaaS leaves the most to the customer, SaaS the least, PaaS sits in between.[3] What never moves: your data, your endpoints, your accounts and who gets access.

Memory hook

IaaS: you get a server. PaaS: you get a place to run code. SaaS: you get the app. Pizza version: IaaS is a rented kitchen, PaaS is take-and-bake, SaaS is eating at the restaurant. Public = shared by strangers, private = yours alone, hybrid = both, community = shared by peers.

Try it (3 minutes)

Sort the cloud services you touch in a normal workday. For each, write IaaS, PaaS or SaaS, and one thing that's still yours to manage.

  1. Your email and chat (Outlook, Teams): SaaS; yours: the accounts, MFA, and who sees which mailbox.
  2. A cloud VM someone built to run an old line-of-business app: IaaS; yours: Windows updates, antivirus, backups inside the VM.
  3. A small internal web app a developer deployed by uploading code: PaaS; yours: the code and its sign-in settings.
One more: your company's device management console (Intune). Which model, and what's still yours? (then click to check)

SaaS: Microsoft runs the service end to end. Still yours: the policies you write, which admins can change them, and the devices you enroll. A wrong compliance policy is a customer mistake, not a provider outage.

Practice

Answer from memory before scrolling back up.

A company wants to run its own hardened OS image and install its own software, but doesn't want to buy or house any servers. Which service model fits?

IaaS rents the hardware, storage and network and leaves the OS to you, so you can bring your own image. PaaS and SaaS hide the OS from you; an on-premises private cloud means buying the servers they want to avoid.

A developer wants to upload web app code and have it run, without ever patching an OS or managing a server. Which service model fits?

PaaS gives a ready platform (OS and runtime managed by the provider); the developer brings only code and data. IaaS would leave OS patching to them, SaaS is a finished app with no place for their code, and community is a deployment model, not a service model.

Five regional hospitals that follow the same health-privacy rules pool their budgets to buy cloud equipment that only they will use. Which deployment model is this?

Community: several organizations with shared needs share the cost of one cloud. It isn't public (strangers can't use it), not private (more than one owner), and nothing says it's mixed with another cloud, so it isn't hybrid.

A company uses a SaaS email service. An attacker phishes a user's password and reads their mailbox. Whose responsibility was protecting that account?

In every cloud model the customer keeps accounts, access, data and devices. The SaaS provider runs the servers and the app; turning on MFA and spotting risky sign-ins is the customer's side of the line.

From memory: the four deployment models in one phrase each, and what you manage in IaaS, PaaS and SaaS. (then click to check)

Public: a provider's cloud shared by many customers. Private: one organization's own. Hybrid: private and public together. Community: several like-minded organizations share one. IaaS: you run the OS and up. PaaS: you run code and data. SaaS: you run data, users and settings. Always yours: data, accounts, access, devices.

Review: earlier lessons

Spaced retrieval: pull these from memory first, then check.

You turn on Hyper-V in Windows 11 Pro. Is the hypervisor now type 1 or type 2, and where does your own Windows run? (lesson 0031, yesterday)

Type 1. The hypervisor loads first, directly on the hardware, and your Windows runs on top of it in the root partition, the one partition allowed to touch the hardware. systeminfo then says "A hypervisor has been detected".

A user plugs their Android phone into a laptop by USB to share its data connection. What is this called, and what appears in the laptop's network adapters? (lesson 0025, 7 days ago)

USB tethering (one device, by cable; a hotspot shares to many by Wi-Fi). A new adapter appears, usually named Remote NDIS based Internet Sharing Device: the phone looks like a wired network card. Sign-ins then come from the carrier's public IP.

A remote cabin office on classic satellite internet complains that video calls lag and drop during storms, though downloads are fine. Name the two weaknesses. (lesson 0018, 14 days ago)

High latency (geostationary satellites are about 35,786 km up, so around 600 ms round trip, which calls feel) and rain fade (weather blocks the signal). Low earth orbit services cut the latency to roughly 25–60 ms.
