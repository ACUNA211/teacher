Pay for what you use, grow when you need it: cloud characteristics

About 10 minutes. Yesterday sorted clouds by who owns them and how much you rent. Today is the other half of objective 4.2: what makes something behave like a cloud at all. Messer lists seven characteristics: shared or dedicated resources, metered utilization, ingress and egress, rapid elasticity, high availability, file synchronization and multitenancy.[1] The win: hear a scenario and name the characteristic.

Why this matters at work

Two of these show up on the help desk every week. File synchronization: when a company points users' Desktop, Documents and Pictures folders at OneDrive (Microsoft calls this Known Folder Move, and Intune can turn it on), a dead laptop no longer means lost files.[3] And multitenancy is why your organization is called a tenant: Microsoft 365 runs many customers on shared infrastructure, kept apart by tenant isolation.[4]

Seven characteristics, three groups

Group them by the question they answer. Three groups are easier to hold than seven names.

QuestionCharacteristicWhat it means
Who owns the hardware?Shared resourcesYou use a provider's data center, shared with others; costs are metered or paid up front[1]
Dedicated resourcesNothing is shared: you build your own data center (or rent hardware only you use) and pay up front[1]
MultitenancyMany customers (tenants) share the same hardware and software, but each one's data stays separate[1]
How do I pay?Metered utilizationYou pay for what you actually use: storage, processing, data moved, like an electric meter[1]
Ingress and egressIngress = data going into the cloud, often free. Egress = data coming out, often charged[2]
How does it behave?Rapid elasticityCapacity grows and shrinks with demand, quickly and usually automatically; users never see it happen[1]
High availabilityThe service stays up when a part fails: redundant servers, links and whole data centers, with automatic failover[1]
File synchronizationThe same files kept up to date on every device and in the cloud: change it on the laptop, see it on the phone[1]

Egress example: Azure says inbound data transfer is free and outbound is billed, after a free monthly allowance.[2] That's why pulling a huge backup out of the cloud can surprise the person paying the bill, while uploading it cost nothing.

Two pairs the exam likes to mix up

Elasticity vs. availability. Ask: is the problem too much demand, or something breaking? A holiday rush that needs more servers → elasticity. A data center or internet link that fails while the service stays up → availability.[1]

Shared resources vs. multitenancy. Shared is about where the hardware lives (a provider's data center, not yours). Multitenancy is about many customers on the same system, kept apart. A SaaS service like Microsoft 365 is both.

Memory hook

Owner (shared, dedicated, multitenant) · bill (metered; in free, out costs) · behavior (stretches, stays up, stays in sync). Elastic stretches for demand; available survives failure.

Try it (3 minutes)

On a Windows PC signed in to OneDrive, open File Explorer and look at the Status column of a synced folder. The icons show file synchronization at work:[3]

  1. A cloud icon: the file lives only in the cloud. It downloads when you open it (Files On-Demand), so it takes no disk space.
  2. A green check: the file is on this device as well as in the cloud.
  3. Right-click a file and choose Free up space: it turns back into a cloud icon. Choose Always keep on this device to pin it.
  4. Then: OneDrive settings → Sync and backup → Manage backup shows whether Desktop, Documents and Pictures are being backed up (Known Folder Move).
A user says "I deleted a file to free up space, and it vanished from my other laptop too." Which characteristic explains it, and what should they have done? (then click to check)

File synchronization: a delete is a change, and sync copies changes everywhere. To save disk space without deleting, use Free up space (keep it cloud-only). The deleted file is usually still in the OneDrive recycle bin for a while.

Practice

Answer from memory before scrolling back up.

An online store's cloud service automatically adds web servers during the holiday rush and removes them in January. Which cloud characteristic is this?

Rapid elasticity: capacity stretches and shrinks with demand. Nothing failed, so it isn't availability; metering is how they're billed for those extra servers, not the scaling itself.

A company uploaded 5 TB of backups to a cloud provider at no transfer cost. The month they restored all of it to their office, the bill jumped. What did they most likely pay for?

Egress is data leaving the cloud, and providers often charge for it, while ingress (the upload) is often free. Restoring 5 TB out of the cloud is a lot of egress.

A provider runs each service in two data centers, each with internet links from two different ISPs. One data center loses power and users notice nothing. Which characteristic is this?

High availability: redundant data centers and links keep the service up when one part fails. Elasticity is about demand, not failure.

Thousands of companies use the same SaaS email platform on the same servers, yet no company can see another's mailboxes. Which characteristic describes this design?

Multitenancy: many tenants share one system while each tenant's data stays isolated. Dedicated would mean nobody shares the hardware at all.

From memory: all seven characteristics, sorted into owner, bill and behavior. (then click to check)

Owner: shared resources, dedicated resources, multitenancy. Bill: metered utilization; ingress (in, often free) and egress (out, often charged). Behavior: rapid elasticity (scales with demand), high availability (survives failures), file synchronization (same files everywhere).

Review: earlier lessons

Spaced retrieval: pull these from memory first, then check.

A vendor's line-of-business app only runs on an old Windows version. Which of the four VM uses is this, and what's the catch? (lesson 0030, 3 days ago)

Legacy software: build a VM with the old OS and keep the modern desktop for everything else. The catch: the old OS still gets no security updates, so give the VM only the network access it truly needs.

A user's Bluetooth headset sounds great for music but terrible the moment a meeting starts. Why, and what's the common workaround? (lesson 0026, 7 days ago)

When the headset's mic turns on, it switches to the Hands-Free Profile, which carries only low-quality mono audio both ways. Workaround: keep the headset as the speaker and pick the laptop's built-in mic (or a USB headset) as the microphone.

You know exactly which cable runs to a user's desk, but you suspect a broken pair. Toner probe or cable tester? (lesson 0019, 14 days ago)

Cable tester: it checks every pin end to end. A toner probe finds a cable and can beep happily on one with a broken pair.
