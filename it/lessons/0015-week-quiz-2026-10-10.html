How to take it

No scrolling back to the lessons until you've answered. A wrong answer followed by the explanation sticks better than a right answer you looked up. Each explanation links to the lesson that taught it, so you know exactly what to reread.

Over the weekend the router for the second-floor subnet was replaced. Monday, every second-floor PC gets a 169.254.x.x address. First-floor PCs are fine, and the one DHCP server sits on the first floor. What's the most likely cause?

A DHCP Discover is a broadcast, and broadcasts stop at the router. To reach a server on another subnet, the router must forward it as a DHCP relay (Cisco's "IP helper"). The old router did; the new one wasn't set up to. A wrong DNS option hands out a bad DNS server, not a 169.254 address. See lesson 0014 and lesson 0001.

Voice calls in the office sound choppy at busy times. A colleague suggests: "Switch the phones to TCP so no packets are ever lost." Why is that a poor fix?

TCP re-sends lost data and delivers it in order, so one lost packet stalls everything behind it. For a live call, audio that arrives late is useless: a short glitch (UDP) beats a pause (TCP). UDP never resends anything, and TCP works on any port. See lesson 0002.

An auditor notes that the company's SPF record ends in ~all rather than -all. What does ~all tell receivers about mail from a server not on the list?

~all is a soft fail: treat unlisted senders as suspicious but still accept the message. -all is a hard fail, which Microsoft recommends for Microsoft 365 domains. rua= is a DMARC tag, not SPF. See lesson 0013.

A user typed their network settings by hand. ipconfig /all shows 192.168.1.42, mask 255.255.255.0, DNS 192.168.1.1, and a blank Default Gateway. The printer down the hall works; pinging a public IP fails. What's wrong?

Local works and everything beyond the subnet fails: that's the no-gateway pattern. A DNS problem would still let a ping to a public IP through. 192.168.1.42 isn't a 169.254 APIPA address, and the printer working rules out a conflict. See lesson 0001.

A new laptop's Intune enrollment fails every time on the office network, but succeeds right away on the user's phone hotspot. The same account works everywhere else. What's the most likely cause?

"Works on the hotspot, fails at the office" points at a box in the office path. A proxy or security appliance that inspects encrypted traffic can break cloud services; Microsoft lists Intune endpoints that shouldn't be inspected. An expired password would fail on the hotspot too. See lesson 0011.

A user types the right password, but the MFA prompt never arrives on their phone, so the sign-in stops there. Which part of AAA hasn't completed?

Password plus MFA is all "who are you?", which is authentication. Authorization (what you may do) only starts once identity is proven. Accounting will log the failed attempt, but it isn't what's blocking. See lesson 0010.

A vendor still sends nightly files to your server over FTP on ports 20 and 21. Security flags it. What's the main problem with FTP?

FTP, like Telnet and HTTP, is unencrypted: the username, password and files cross the network in the clear. It runs over TCP 20/21, not UDP 53 (DNS), and has nothing to do with RDP. See lesson 0003.

Ten minutes ago an admin changed the A record for intranet.example.com to a new server's address. Some users reach the new server; others still land on the old one. What explains it?

Every record carries a TTL: how long clients and other DNS servers may keep a cached answer. Users who looked the name up before the change keep the old address until their copy expires. MX only matters for mail, and the A record alone is enough for a web name. See lesson 0012.

Two neighboring access points in a US office are set to 2.4 GHz channels 3 and 5. Users between them report slow, unreliable Wi-Fi. Which change fixes the overlap?

Each 2.4 GHz channel overlaps its neighbors, so only 1, 6 and 11 stay clear of each other. Channels 3 and 5 (or 2 and 4, or 3 and 4) interfere; 12 and 13 aren't allowed for normal Wi-Fi in the US. See lesson 0006.

A fixed wireless link between two buildings runs on unlicensed 5 GHz and keeps dropping when a neighbor's equipment is busy. Which change best removes that interference?

Unlicensed spectrum is free but shared with anyone nearby. Licensed spectrum is paid-for, exclusive use, so no one else is allowed to transmit there. Power is capped by regulators, Bluetooth reaches about 10 meters, and directional antennas are what aim the beam in the first place. See lesson 0009.

A laptop gets an 8-hour DHCP lease at 9:00 AM. At 10:00 AM the DHCP server that issued it goes offline and stays down. When does the laptop first broadcast to any DHCP server?

At T1 (50%, 1:00 PM) the laptop asks only its own server, which doesn't answer. At T2 (87.5%, seven of eight hours: 4:00 PM) it broadcasts to any server. If nothing answers by 5:00 PM, the lease is gone and it starts DORA again. See lesson 0014.

To authorize a newsletter service, an admin adds a new TXT record, v=spf1 include:news.example.net -all, next to the existing SPF record. Now all company mail fails SPF. Why?

A domain may publish only one SPF record; with two, receivers treat SPF as broken for everything. The fix is one record with an extra include:. SPF is a TXT record, MX only handles incoming mail, and -all only fails servers not on the list. See lesson 0013.

A warehouse scanner supports only 802.11n. The new access points broadcast on 5 GHz and 6 GHz only. What happens when the scanner tries to join?

802.11n (Wi-Fi 4) runs on both 2.4 and 5 GHz, and standards are backward compatible within a band, so it joins on 5 GHz at n speeds. 6 GHz needs Wi-Fi 6E or 7 on both ends. See lesson 0007.

A new firewall is set to send its logs to the central syslog server, but nothing arrives. Ping between them works. Which traffic do you check is allowed along the path?

Classic syslog sends messages over UDP 514. Ping working proves the path; the port is the next suspect. 445 is SMB, 67 is the DHCP server, and 389 is LDAP. See lesson 0010.

A user can open \\192.0.2.20\share, but \\files.example.com\share fails with "path not found." Where is the problem most likely?

The share opens by IP, so the network, SMB on 445 and permissions all work. Only the name fails, so check DNS: does Resolve-DnsName files.example.com return an A record with the right address? See lesson 0001, lesson 0012 and lesson 0005.

Explain it in your own words

Say or write the answer before you open each one. If you can explain it to a coworker, you know it.

A manager asks why the office printer should get a DHCP reservation but the router needs an exclusion. Explain the difference in two sentences. (lesson 0014)

A reservation tells DHCP "always give this address to this MAC," so the printer keeps the same address but still gets its gateway and DNS from DHCP. An exclusion tells DHCP "never hand this address out," which protects devices like the router whose address is typed in by hand.

Someone is spoofing your company's From address. Explain, using the guest-list, wax-seal and bouncer picture, what SPF, DKIM and DMARC each do and which one tells receivers to act. (lesson 0013)

SPF is the guest list: which servers may send for the domain. DKIM is the wax seal: the message was signed by the domain and not changed on the way. DMARC is the bouncer's instructions: if SPF or DKIM doesn't pass (and line up with the From domain), quarantine or reject the message, and report it. Only DMARC tells receivers what to do.

Load balancer vs. proxy: which way does each one "face," and what does an outside website see in each case? (lesson 0011)

A load balancer faces inward: it sits in front of your servers, and visitors see one address while many servers share the work. A proxy faces outward: it makes requests for your users, so the outside website sees the proxy's address, not each PC's.

Sort fixed wireless, Bluetooth, RFID and NFC by range, and give one work example of each. (lesson 0009)

Fixed wireless: kilometers (linking a second building). Bluetooth: about 10 meters (headsets, mice). RFID: centimeters to meters (door badges, inventory tags). NFC: about 4 centimeters (tapping a security key to a phone, tap-to-pay).
