Web and remote access ports

About 10 minutes. By the end you know six port numbers the exam expects cold, which of them are safe to use, and how to see the ports your own PC is using right now.

Why this matters at work

Almost every cloud admin portal and sign-in page you use runs over one port: 443. When a user can browse the web but can't reach a remote desktop, or a helpdesk tool connects on one network and not another, the question from lesson 0002 comes back: which port does this need, and is something blocking it? Knowing the numbers by heart makes that question fast.

Two families, six numbers

The A+ objectives list the common ports you must know.[1] Today is the first half: the ports for the web and for controlling or copying to another machine. All of them use TCP.

PortProtocolWhat it doesEncrypted?
80HTTPWeb pagesNo
443HTTPSWeb pages, secured with TLSYes
23TelnetText console on a remote deviceNo
22SSHText console on a remote deviceYes
3389RDPFull Windows desktop, remotelyYes
20, 21FTPCopy files: 21 for commands, 20 for data (active mode)No

The pattern: old and plain, new and encrypted

Notice the pairs. HTTP and HTTPS do the same job, but only HTTPS encrypts. Telnet and SSH both give you a command line on a remote device, but Telnet sends everything, passwords included, in the clear, while SSH encrypts the whole session.[2] That's why SSH replaced Telnet, and why the exam likes to ask "which should you use?"

FTP is the odd one: two ports. Port 21 carries the commands (log in, list, get this file) and, in active mode, port 20 carries the file data itself.[2] Plain FTP is unencrypted too, so its login is readable by anyone on the path.

RDP on 3389 is Microsoft's Remote Desktop: the whole Windows screen, keyboard and mouse, across the network.[1] It's the one number above 1023 in today's list, so it's easy to remember as "the big one".

Memory hooks

20-21-22-23 climb in order: FTP, FTP, SSH, Telnet. 80 is the web, and the secure web is 443. Remote Desktop is the only four-digit one: 3389.

Coming from programming: a URL like https://example.com never shows 443 because the browser fills in the default port for the scheme. Write http://example.com:8080 and you're telling it to use a non-default port instead.

Try it (2 minutes)

See which remote ports your PC is talking to right now. In PowerShell, Get-NetTCPConnection lists TCP connections.[3]

  1. Open a browser with a few tabs, then open PowerShell.
  2. Run: Get-NetTCPConnection -State Established | Group-Object RemotePort | Sort-Object Count -Descending
  3. Look at the Name column (the remote port). Expect 443 near the top: that's your browser, your mail and most cloud apps.
Count Name
----- ----
   27 443
    2 80
    1 5228

Your numbers will differ. The LocalPort on each of those connections is the ephemeral port from lesson 0002. Seeing 80 means something is still using plain, unencrypted HTTP.

Practice

Answer from memory before scrolling back up.

A network switch can be managed from a text console using either Telnet or SSH. Which should you choose, and why?

SSH (port 22) and Telnet (port 23) do the same job, but Telnet sends everything in plain text, including your password. SSH encrypts the whole session. Port 3389 is RDP, not SSH.

A user can browse websites fine, but connecting to their office PC with Remote Desktop times out. Which port is most likely blocked?

Remote Desktop (RDP) uses TCP 3389. Browsing works, so 443 is fine. Port 22 is SSH and 21 is FTP control, neither of which Remote Desktop uses.

A firewall log shows traffic from a PC to a server on TCP port 21, then a second connection on TCP port 20. What is the PC doing?

FTP uses port 21 for commands and, in active mode, port 20 for the file data. An encrypted console would be SSH (22), a plain web page HTTP (80), and a remote desktop RDP (3389).

An internal web app's login page loads over http:// on port 80. Why is that a problem worth reporting?

HTTP on port 80 isn't encrypted, so anyone who can capture the traffic can read the password. HTTPS on 443 fixes that with TLS. Browsers still allow port 80, it uses TCP, and it can carry forms; it just can't protect them.

From memory: give the port for HTTP, HTTPS, SSH, Telnet, RDP and FTP, and say which are unencrypted. (then click to check)

HTTP 80, HTTPS 443, SSH 22, Telnet 23, RDP 3389, FTP 20/21. Unencrypted: HTTP, Telnet and FTP.

Review: earlier lessons

Spaced retrieval: pull these from memory first, then check.

Why does a live video call usually use UDP rather than TCP? (lesson 0002, yesterday)

UDP doesn't stop to re-send lost data. For live audio and video a late packet is useless anyway, so a small glitch beats TCP's pause-and-retry.

A PC can ping a server, but the app on it won't connect. What's your first suspect, and what PowerShell command tests it? (lesson 0002, yesterday)

The port: the service isn't running or a firewall blocks it. Test with Test-NetConnection server -Port N and read TcpTestSucceeded.

A laptop reaches the local printer but no internet sites, not even by IP address. Which of the four settings do you check? (lesson 0001, 2 days ago)

The default gateway. Local traffic doesn't need it, but everything outside the subnet does.
